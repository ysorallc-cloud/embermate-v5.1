## Goal

EmberMate is a React Native + Expo SDK 52 caregiver mobile app. The current
work is a long UX restructure on the **`v6-restructure`** branch, shipping
sub-phase by sub-phase (15.x → 16.x → 22.x), strict TDD: failing test →
implement → commit + push, one sub-phase per session.

caregiver workflow that reads as a handoff document (caregiver →
next-caregiver, or caregiver → next doctor visit), not as a workspace.

   `/visit-prep` route. Consolidated to 14d + `/visit-prep` (more inclusive
   window, canonical route). `care-report.tsx:884` still points at
   `/provider-prep` — **filed for a separate audit scope**.

2. **15.8 days-param semantic gotcha:** spec asked to set `days={N}`
   dynamically. Verification showed `days` is the report-lookback enum
   (`'7' | '14' | '30'`), NOT days-until-appointment. Setting it dynamic
   would silently fall through the validator. **Kept at 14** — value is
   intentional. Phase 16.2 added a contract pinning N is days-until at

3. **15.10 BP averaging discrepancy:** the "This Week" card showed 145/88
   while the Vitals tile shows 132/82. Removing the duplicate surface does

   contracts that the canonical BP path stays intact.

   "Care report (PDF)" but `Share.share` only sent plain text — broken
   in practice. Phase 15.11.1 dropped "(PDF)"; Phase 16.4 hid the option

7. **22.2 coral semantics vs Phase 7 budget:** theme tokens carry a Phase 7

   with coral as a retired decorative accent. 22.2 **reframed coral as
   semantic** ("handoff action required") on STILL PENDING — Phase 7 was

8. **22.3 time-of-reading parens deferral:** `"Vitals (8a)"` parens come

## Conventions for the next session

These are workflow contracts the user has established across sub-phases —
worth following without re-asking:

- **TDD strict.** Failing test → confirm RED → implement → confirm GREEN →
  commit + push. One sub-phase per commit. Don't bundle.
- **Audit findings first.** Each sub-phase opens with a brief findings
  report (surface ambiguities + propose resolutions). Don't proceed until
  the user confirms, unless the resolutions are obvious.
- **Surface watch-fors.** When a spec contains a "watch for" item, address
  it explicitly in the commit message, even if no change was required.
- **Retirement pins.** When legacy tests assert presence of something
  being retired, flip them to absence pins documenting the retirement —
  don't delete the tests outright. See `journalDisclaimer.test.tsx`,
  `journalHeaderMoodLine.test.tsx`, `sampleIndicatorTap.test.tsx` for
  the pattern.
- **`codeOnly()` helper.** Source-level audits should strip comments
  before regex matching so retirement prose doesn't false-positive
  against absence pins. Pattern established in 15.9, used throughout 22.x.
- **Intentional orphan files.** Component files retired from production
  consumers stay on disk with an "intentional orphan" pin in a relevant
  test. Don't delete them as a side-effect of the retiring sub-phase.
